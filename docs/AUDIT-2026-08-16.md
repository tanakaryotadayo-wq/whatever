## Critical findings

### F1 — Provider state was stale

`CODEX_MODE.md` said `Official Codex live three-run = NOT RUN`.

Actual provider branch evidence shows:

- hosted macOS probe: BLOCKED because `OPENAI_API_KEY` secret is absent
- GitHub Models single-model attempt: FAILED
- GitHub Models matrix: FAILED
- valid three-run PASS receipt: absent

Correct status:

```text
PROVIDER_ATTEMPTED_FAILED_AND_BLOCKED
```

### F2 — Newer provider workstream was omitted

The mode pointed at `akashic/p0-codex-app-server-live-two-turn`, while the active review surface is:

```text
branch: akashic/v0.10-codex-app-server-live
PR: #15 (Draft)
```

The prior branch is now a superseded staging/recovery surface.

### F3 — Misleading Drive release records

Drive `releases/` contained:

- an empty folder named `v0.10.0-codex-app-server-live`
- a ZIP named `v0.10.0_codex_app_server_live_final_evidence.zip`

The ZIP contains only a `NO_RESULT` report. These records must be quarantined outside `releases/` and renamed with `NO_RESULT`.

### F4 — Mutable state was embedded in a 10KB operating document

The mode had no separate Current State file, freshness guard, status command, attempt ledger, or machine validator. A future session had to read the full document and could still use stale heads.
